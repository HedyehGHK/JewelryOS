# JewelryOS — سامانه موجودی و فاکتور طلافروشی

برنامه تحت وب برای فروشگاه طلا: کاتالوگ کالا، ورود اطلاعات از اکسل، نرخ روز طلا، قیمت‌گذاری خودکار، صدور فاکتور PDF فارسی، ابطال/مرجوعی، داشبورد و گزارش فعالیت‌ها.
رابط کاربری کاملاً فارسی و راست‌به‌چپ است و روی کامپیوتر، تبلت و موبایل (در شبکه داخلی مغازه) کار می‌کند.

| لایه | فناوری |
|---|---|
| رابط کاربری | Angular 22 + Angular Material (RTL، فونت وزیرمتن محلی — بدون نیاز به اینترنت) |
| سرور | ASP.NET Core 8 (Minimal API) |
| پایگاه داده | SQLite (یک فایل) با EF Core Migrations |
| فاکتور PDF | QuestPDF (A5، راست‌به‌چپ، تاریخ شمسی) |
| اکسل | ClosedXML |
| تست | xUnit (قیمت‌گذاری، فروش همزمان، ابطال، اکسل) + Vitest |

## اجرای سریع (ویندوز)

پیش‌نیاز: [.NET SDK 8 یا جدیدتر](https://dotnet.microsoft.com/download).

1. روی `run.bat` دوبار کلیک کنید (یا در ترمینال: `cd backend/JewelryOS.Api` و `dotnet run`).
2. مرورگر را باز کنید: **http://localhost:5080**
3. ورود با **admin / admin1234** (بعد از ورود، برنامه از شما می‌خواهد رمز را عوض کنید).
   در حالت توسعه یک کاربر فروشنده نمونه هم ساخته می‌شود: **seller / seller1234**.

در حالت توسعه (`run.bat`) داده‌های **ساختگی** (۱۵ کالا و یک نرخ نمونه) ساخته می‌شود تا بتوانید برنامه را امتحان کنید.
رابط کاربری از قبل ساخته شده و داخل `backend/JewelryOS.Api/wwwroot` است؛ برای اجرای ساده به Node.js نیازی نیست.

### اجرای تست‌ها
`test.bat` یا `cd backend && dotnet test`

### نسخه دسکتاپ (پیشنهادی برای مغازه)
برنامه به شکل یک اپ ویندوزی با فایل نصبی ساخته می‌شود (Electron). سرور برنامه پشت پرده خودکار اجرا می‌شود و مرورگر لازم نیست.

1. پیش‌نیاز روی کامپیوتر خودت: .NET SDK 8+ و [Node.js 20+](https://nodejs.org).
2. `build-desktop.bat` را اجرا کن. بار اول چند دقیقه طول می‌کشد.
3. خروجی: `desktop\dist\JewelryOS Setup 1.0.0.exe` — همین یک فایل را برای مغازه بفرست.
4. در مغازه نصب کنند. چون فایل امضای دیجیتال ندارد، ویندوز ممکن است پیام «Windows protected your PC» بدهد: **More info ← Run anyway**.
5. اطلاعات در `%APPDATA%\JewelryOS\data\jewelryos.db` ذخیره می‌شود و با حذف یا به‌روزرسانی برنامه پاک **نمی‌شود**.
6. وقتی برنامه باز است، موبایل و کامپیوترهای دیگرِ وصل به همان مودم هم از آدرسی که در صفحه **تنظیمات** (بخش «استفاده از موبایل…») نوشته شده وارد می‌شوند.
   منوی پنجره با کلید Alt ظاهر می‌شود.
7. تنظیم پورت و دسترسی شبکه: `%APPDATA%\JewelryOS\config.json` (`port`، `allowNetwork`).

برای امتحان نسخه دسکتاپ در حالت توسعه (با داده نمونه): `desktop-dev.bat`

### نصب در مغازه بدون Electron
1. `publish-store.bat` را اجرا کنید. پوشه `publish` ساخته می‌شود که **بدون نصب .NET** روی ویندوز کار می‌کند.
2. پوشه را روی کامپیوتر مغازه کپی و `JewelryOS.Api.exe` را اجرا کنید.
3. در همان کامپیوتر: `http://localhost:5080` — در سایر دستگاه‌های شبکه مغازه: `http://IP-کامپیوتر:5080`
   (ممکن است لازم باشد پورت 5080 را در فایروال ویندوز باز کنید).
4. در حالت نصب (Production) داده نمونه ساخته **نمی‌شود**. اول نرخ روز را ثبت کنید، بعد کالاها را از اکسل وارد کنید.
5. رمز پیش‌فرض را می‌توانید قبل از اولین اجرا در `appsettings.json` (بخش `Seed`) تغییر دهید.

### پشتیبان‌گیری
- مدیر در صفحه **تنظیمات ← دانلود نسخه پشتیبان** یک کپی سالم از پایگاه داده دریافت می‌کند.
- یا فایل `storage/jewelryos.db` (کنار برنامه) را وقتی برنامه بسته است کپی کنید.
- برای بازگردانی: برنامه را ببندید، فایل پشتیبان را با نام `jewelryos.db` در پوشه `data` بگذارید و دوباره اجرا کنید.
- پیشنهاد: هر شب یک نسخه روی فلش یا کامپیوتر دیگر نگه دارید.

### توسعه رابط کاربری
```
cd frontend
npm install
npm start          # http://localhost:4200 (درخواست‌های /api به سرور 5080 می‌روند)
npx ng build       # خروجی مستقیم در backend/JewelryOS.Api/wwwroot
npx ng test --watch=false
```

## قیمت‌گذاری

جزئیات و مثال حل‌شده در [docs/pricing.md](docs/pricing.md). خلاصه:

```
ارزش طلا  = وزن × نرخ هر گرم ۱۸ عیار × عیار ÷ ۷۵۰
اجرت      = ارزش طلا × درصد اجرت کالا
سود       = (ارزش طلا + اجرت) × ۷٪
مالیات    = (اجرت + سود + سنگ) × ۱۰٪        ← قابل تغییر به «کل مبلغ» در تنظیمات
جمع ردیف  = طلا + اجرت + سود + سنگ + مالیات
جمع فاکتور گرد می‌شود به نزدیک‌ترین مضرب ۱٬۰۰۰
```

درصد سود، درصد مالیات، پایه مالیات و واحد گرد کردن در صفحه **تنظیمات** قابل تغییر است.
**قبل از استفاده واقعی این عددها را با صاحب مغازه و قانون روز تطبیق دهید.**

## تغییر ساختار پایگاه داده (Migrations)

هر بار که مدل داده را عوض می‌کنید (`Domain/Entities.cs` یا `Data/AppDb.cs`)، یک migration بسازید:

```
.\db-migration.bat AddSomethingName
```

برنامه در اجرای بعدی، **قبل از** اعمال تغییر یک نسخه پشتیبان در پوشه `backups` کنار فایل پایگاه داده می‌گیرد و بعد جدول‌ها را به‌روز می‌کند؛ اطلاعات قبلی حفظ می‌شود.
اولین بار (یک‌بار برای همیشه): `.\db-migration.bat InitialCreate`. پایگاه داده‌هایی که قبل از آن ساخته شده‌اند خودکار به این migration وصل می‌شوند.
هیچ‌وقت فایل‌های داخل `Data/Migrations` را که قبلاً منتشر شده‌اند دستی تغییر ندهید یا پاک نکنید.

## فرمت فایل اکسل

ردیف اول عنوان ستون‌هاست. ستون‌ها از روی عنوان شناسایی می‌شوند و در صفحه پیش‌نمایش قابل تغییرند.
فایل نمونه: `sample-data/products-template-sample.xlsx` (یا دکمه «قالب با داده نمونه» در برنامه).

| ستون | اجباری | توضیح |
|---|:-:|---|
| کد کالا | ✓ | یکتا. اگر کد قبلاً ثبت شده باشد، کالا به‌روزرسانی (یا بسته به انتخاب شما رد) می‌شود — هرگز تکراری ساخته نمی‌شود |
| نام کالا | ✓ | |
| دسته‌بندی | | انگشتر، گردنبند، … |
| عیار | | ۷۵۰ (پیش‌فرض) یا ۸۷۵، ۹۰۰، … — عدد ۱۸/۲۱/۲۴ هم پذیرفته و به هزارم تبدیل می‌شود |
| وزن (گرم) | ✓ | ارقام فارسی، «٫» یا «/» به‌عنوان ممیز پذیرفته می‌شود |
| درصد اجرت | | مثلاً ۱۸ یا ۱۸٪ |
| ارزش سنگ | | مبلغ ثابت برای هر عدد |
| نوع (تکی/تعدادی) | | تکی = هر قطعه منحصربه‌فرد (موجودی ۰ یا ۱)، تعدادی = چند عدد مشابه با یک کد |
| موجودی | | پیش‌فرض برای تکی ۱ |
| توضیحات | | |

فایل `sample-data/products-messy-test.xlsx` عمداً خطا دارد تا اعتبارسنجی را امتحان کنید.

## اصول طراحی داده

- مبالغ همیشه `decimal` هستند (هرگز float).
- هر تغییر موجودی یک ردیف در «تاریخچه موجودی» با دلیل و نام کاربر دارد؛ هیچ سابقه‌ای حذف نمی‌شود.
- فاکتور **نسخه ثابت قیمت‌ها** (نرخ، اجرت، سود، مالیات هر ردیف) را ذخیره می‌کند؛ تغییر نرخ یا تنظیمات روی فاکتورهای قبلی اثر ندارد.
- فروش، ردیف‌های فاکتور و کسر موجودی در یک تراکنش ثبت می‌شوند. کسر موجودی با `UPDATE … WHERE موجودی کافی` انجام می‌شود، پس دو فروشنده همزمان نمی‌توانند یک قطعه را دو بار بفروشند.
- ابطال/مرجوعی فاکتور را حذف نمی‌کند؛ وضعیت را تغییر می‌دهد و موجودی را با حرکت جبرانی برمی‌گرداند.
- هر کار مهم (ورود، فروش، ابطال، تغییر نرخ و تنظیمات، اصلاح موجودی، ورود اکسل) در «گزارش فعالیت‌ها» ثبت می‌شود.

## محدودیت‌ها و کارهای بعدی

- مرجوعی فقط برای کل فاکتور است (مرجوعی بخشی از اقلام هنوز پیاده نشده).
- تخفیف جداگانه ندارد؛ مدیر می‌تواند درصد اجرت را در فاکتور کم کند.
- اتصال HTTPS برای شبکه داخلی تنظیم نشده؛ اگر برنامه روی اینترنت قرار گیرد باید HTTPS فعال شود.
- عکس کالا، خرید طلای مستعمل از مشتری و تسویه چندروشی (نقد/کارت) در نسخه بعدی.

مجوز فونت وزیرمتن: SIL OFL (فایل `backend/JewelryOS.Api/Fonts/OFL.txt`). QuestPDF با مجوز Community برای کسب‌وکارهای با درآمد سالانه کمتر از ۱ میلیون دلار رایگان است.
